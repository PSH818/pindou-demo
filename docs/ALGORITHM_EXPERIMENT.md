# 双算法对比实验

2026-09-09 更新。原算法显示为「经典模式」；`perceptual-v1` 显示为「保真模式（测试版）」。首次使用默认经典，之后记住最近成功采用或直接生成的模式。

## 使用

上传图片后，在转换设置的「转换算法」中选择版本，或点击「对比两种算法」。重新生成面板和桌面调参栏也提供同一入口。

对比页使用相同品牌、网格尺寸、模式、抖动开关和合并数值，读取图片一次，再将相同像素数据分别送入两个独立 Worker。支持同步放大、同步滚动、查看原图，展示用色数、珠子数、孤立格数和本次耗时。点击「采用这张图纸」后，保存预览中的确切结果并进入编辑器；取消或仅查看预览不新建图纸。已有图纸重转时，采用结果覆盖当前图纸，与既有重新生成行为一致。

## 实现与保护边界

「两个版本都保留」会原子性新增两张独立图纸，以模式名称区分，返回首页；不覆盖当前图纸、不改变偏好。如果本地剩余容量不足两张，则全部不保存并允许重试。仅切换下拉选项、预览、取消和查看历史图纸均不改变偏好。

新生成图纸记录 `conversionAlgorithm`、`conversionVersion` 和 `conversionParams` 参数快照。版本号 `legacy-frozen-1` / `perceptual-1` 是本项目内部版本，不代表上游版本。后续手工编辑保留来源记录；旧图纸仍可打开，不伪造其缺失的参数或版本。未新增原图持久化，因此这些元数据不等于跨会话一键重算能力。

| 项目 | 原算法 | 感知保真 v1 |
|---|---|---|
| Worker | `src/workers/imageProcessor.js` | `src/workers/perceptualProcessor.js` |
| 实现核心 | 原有文件，未改动 | `src/workers/perceptualCore.js` |
| 取样 | RGB bucket 主色 / RGB 均值 | 精确覆盖面积与 alpha 权重 |
| 卡通模式 | RGB bucket 投票 | 感知近色投票；高反差深色轮廓占比 ≥35% 时保护 |
| 写实模式 | sRGB 均值 | 线性光均值 |
| 选珠子颜色 | 5-bit RGB 查表 | 精确 RGB 缓存 + Oklab 最近色 |
| 合并 | RGB 距离内按频率吸收 | 感知距离 + 相对初始选色的平均/最大误差增量限制 |
| 抖动 | 原 Floyd–Steinberg | 蛇形扫描扩散，透明格不接收或传递误差 |

新算法仅复用既有消息协议、色板与外层图片读取方式。`imageProcessor.js`、`dither.js`、`colorMatch.js` 三个原文件均由 SHA-256 回归测试锁定，逐字节未改。既有图片预缩放（最长边 400）也保持不变。

Oklab 矩阵采用 Björn Ottosson 公开的 [Oklab 定义与公有领域实现](https://bottosson.github.io/posts/oklab/)，2021-01-25 修订矩阵。

合并数值不具有跨算法相同色差单位：新算法半径为 `strength × 0.0012`，平均允许误差增量为 `(strength × 0.00065)²`，任一格不超过该增量的两倍。误差始终相对首次选色计算，防止多次合并累积越界。

## 如何判断哪套更合适

先将合并设为 0、关闭抖动，观察基本选色与线条；再以实际用色数接近为目标分别调整合并，比较手工成本与细节。使用相同原图、尺寸和品牌，分别试卡通图、透明背景线稿、照片和渐变。

孤立格可能是杂色，也可能是眼睛或高光。颜色更少不必然更好；新算法的暗线保护可能略微加粗轮廓，线性光均值也会比原算法的均值模式更明亮。界面没有计算带倾向性的总分，也不自动宣布胜者。

耗时包含 Worker 初始化和计算，不含图片读取和预览绘制。原算法先运行，缓存与设备负载可能影响结果，单次耗时不能作为普遍性能排名。

## 验证记录

- `npm run check`：类型检查、20 项测试、生产构建通过。
- 原算法文件完整性、透明输入、非连续颜色 ID、非整数缩放覆盖、线性光均值、透明 RGB 污染、黑色孤立细节、跨格细线、抖动、确定性和协议兼容测试通过。
- Chrome 无界面测试覆盖：双结果、预览不写存储、同步滚动、390px 手机布局、采用后保存、历史重开、单独运行新算法和取消；无浏览器异常。
- 双模式补充验证：实际采用图与预览逐像素一致、偏好记忆、仅选择不记忆、参数快照、同时新增两个版本、原图纸不覆盖、重复 ID 的事务回滚、49 张时拒绝新增两张且没有部分写入、失败后按钮恢复可操作。
- 合成测试图（渐变背景、深色轮廓、眼睛、嘴、透明角；60×48；MARD；卡通；合并30；抖动关闭）：原算法9色，新算法10色；均2871粒、0个孤立格。本次两者耗时均约0.07秒。这个小样本只能证明流程可用，不能证明新算法全面优于原算法。
